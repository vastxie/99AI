# 文档写作规范

本规范约束 `site/` 站点全部页面的行文与结构，新增或修改页面前先读一遍。本文件已通过 `config.mts` 的 `srcExclude` 排除，不会出现在线上站点。

## 行文六条

1. **表格只放可枚举的事实**。字段、默认值、尺寸、渠道、版本号可以进表格；第二列在写完整句子的表格，一律改写成正文或列表。单页表格一般不超过 2 张。
   - 好表格：基础信息页的「配置项 / 说明 / 建议」。
   - 坏表格：`| 耗时信息 | 让用户知道任务执行了多久 |` —— 这类内容并进正文一句话。
2. **不写自我阐释**。「X 的作用是…」「不是 A，而是 B」「这样做的目的是…」这类句式删掉，直接陈述事实和操作。设计意图确有必要说明时，用一句陈述句融进正文。
3. **称呼统一叫「用户」**。仅在同一处需要与管理员对比、不区分会产生歧义时才写「终端用户」。受众描述全站只在产品首页出现一次，其他页面不再自我介绍。
4. **单一信源**。每个概念只在一个页面完整展开，其余页面一句话带过并链接：
   - 内核 / 扩展包的定义与清单 → `guide/index.md`
   - 扩展包开关与关闭后的影响 → `deployment/packs.md`
   - 部署流程与环境变量 → `deployment/index.md`
   - MCP、渠道服务与垂直包 → `deployment/integrations.md`
5. **列举克制**。正文叙述里能力列举最多 3 项加「等」；同一页同一串列举不出现第二次。配置页中需要完整枚举的事实（支持的渠道、模型、格式）不受此限。
6. **少用「加粗开头：解释」式列表**。连续的 `**词**：解释` 超过 3 条就考虑改写成正文段落。

## 截图规范

- 占位一律写成 HTML 注释，不进入渲染页面：`<!-- 截图占位 USER-01-HOME：用户端首页总览。 -->`
- 正式截图用相对路径图片，alt 写清楚画面内容。
- 三类截图标记：后台配置图 `CFG-...-01`；用户端入口图 `CFG-...-USER-ENTRY-01`；用户端效果图 `CFG-...-USER-EFFECT-01`。凡影响用户端展示或操作的配置，配套补一张用户端截图，让读者知道「在哪里配」和「配完用户看到什么」。
- 页面里不放「截图清单」章节；待补截图检索 `截图占位` 注释即可汇总。

## 其他约定

- 带 `{#id}` 的标题和被 `config.mts` 侧边栏引用的标题，不得改名或删除。
- 页尾「相关文档」最多 4 条，只放强相关页面。
- markdownlint 配置见 `.markdownlint.json`（MD022、MD036 关闭，其余默认）。
