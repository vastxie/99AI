# 用户策略

新用户注册送多少积分、签到给多少奖励、游客能体验多久等，都在用户策略里调整。

## 后台入口

- **菜单路径**：用户运营 → 用户策略
- **后台地址**：`/user/settings`

## 配置项

| 配置项 | 说明 |
| --- | --- |
| 是否开启注册赠送 | 开启后，新用户注册成功会获得积分 |
| 注册赠送积分 | 注册赠送的积分数量 |
| 最大登录设备数 | 同一账号最多允许同时登录的设备数；超出时最久未活动的设备下线，调低后从各账号下次登录起生效 |
| 开启签到奖励 | 开启后，用户端可以通过每日签到获得积分 |
| 签到赠送积分 | 每次签到发放的积分数量 |
| 开启访客功能 | 开启后，未登录用户可以使用限定额度体验平台 |
| 每日积分额度 | 游客每天可使用的积分额度；大于 0 时视为开启游客功能 |

最大登录设备数由内核提供；「额度与赠送」卡片（注册赠送、签到奖励、访客功能与每日积分额度）由商业包提供，未装载时不显示。

## 使用建议

### 注册赠送

适合希望降低新用户体验门槛的站点。建议赠送额度能覆盖几次基础对话，但不要过高，避免被批量注册消耗资源。

示例：

| 运营阶段 | 建议 |
| --- | --- |
| 内测期 | 可适当提高注册赠送，方便用户试用 |
| 正式运营 | 控制在基础体验范围内 |
| 风险较高时期 | 暂时关闭或降低额度 |

### 最大登录设备数

建议设置为 `3` 到 `5`。设备数过低会影响正常用户，过高则可能增加账号共享风险。

### 签到奖励

签到适合提升留存，但赠送额度要和模型消耗成本匹配。建议先设置小额奖励，观察每日消耗后再调整。

### 游客功能

访客功能适合让未注册用户先体验。开启后，`每日积分额度` 建议从小额度开始，例如只覆盖少量基础对话。

如果你不希望未登录用户使用平台，请关闭访客功能，或把每日积分额度设为 `0`。

## 常见问题

### 访客功能开关和每日积分额度是什么关系？

当每日积分额度大于 `0` 时，系统视为开启访客功能；等于 `0` 时视为关闭。关闭开关会把额度保存为 `0`（并记住原来的额度，再次开启时恢复）；把额度改成 `0` 并保存后，开关随之关闭。保存失败时开关与额度一起回到原来的状态。

### 开启注册赠送后必须填写积分吗？

建议填写。开启后如果积分为空或过低，新用户可能仍然无法完成有效体验。

### 修改最大设备数会踢掉已登录用户吗？

该配置主要影响后续登录和会话控制。已经在线的设备是否立即受影响，取决于后端会话刷新和校验时机。
