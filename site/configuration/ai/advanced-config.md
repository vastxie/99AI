# 全局配置

全局配置只保留两组内容：Agent 的单次请求执行上限与等待模型的时间上限，以及作用于所有对话的模型参数和输入限制。工具执行本身发生在每个用户独立的沙箱里，不需要在这里配置。

- 后台入口：AI 能力 / 全局配置

## 配置概述

| 区域      | 作用                                   |
| --------- | -------------------------------------- |
| Agent 设置 | 限制一次用户请求里 Agent 最多调用多少轮工具，以及等模型开始响应的最长时间 |
| 其他配置  | 输入框字符上限和全局头部预设 |

字段修改后会在失焦时自动保存，不需要单独点击保存按钮。

## 配置项详解

### Agent 设置

| 配置项           | 说明                                                   | 建议                                   |
| ---------------- | ------------------------------------------------------ | -------------------------------------- |
| 工具调用轮次上限 | 一次用户请求里，Agent 读写文件、运行命令等工具调用的最大轮次（可填 1–50，默认 25） | 保持默认；任务经常提前收尾时再逐步调高 |
| 模型首次响应等待上限 | 每次向模型发出请求后，等它开始响应的最长时间，单位秒（可填 10–600，默认 120） | 保持默认；用户常遇到「模型响应超时，请重试」时调大 |

接近上限时，Agent 会在最后几轮收到剩余轮次提醒，先停止继续搜集、整理已有结果并交付；轮次用完后还能再给出一次不调用工具的最终答复。如果仍在上限处继续调用工具，本轮会停止，回复末尾显示「已达本轮工具调用次数上限」，用户可以继续追问让它接着做。

已有站点保存的配置值会继续生效；要使用新的默认轮次，请在本页调整。服务端会把超过 50 的整数限制为 50，空值、非正数和非整数按默认 25 处理。

等待上限只管「请求已经发出、模型还没有任何响应」这一段：超过后本轮以「模型响应超时，请重试」结束，不会自动重发；模型服务直接报错（密钥无效、额度不足、服务不可用等）不受它影响，仍然立刻返回。推理模型、经转换网关接入的模型开始响应较慢，可以按实际情况调到 300 甚至 600。服务端把配置值限制在 10–600，空值与非正数按默认 120 处理。

回复开始之后另有一条固定的上限：连续 10 分钟没有任何输出，本轮以「模型长时间没有输出，已中断，请重试」结束，已经输出的内容会保留。这一项不可配置。

### 其他配置

| 配置项         | 说明                 | 建议                             |
| -------------- | -------------------- | -------------------------------- |
| 输入框字符上限 | 限制用户单次输入长度 | 默认 20000，避免超长输入拖慢系统 |
| 全局头部预设   | 全局系统提示词       | 只写必要约束，不写长篇营销文     |

## 配置建议

- 全局头部预设会影响所有对话，适合写原则、边界和安全要求，不适合写具体任务模板。
- 工具调用轮次上限越高，复杂任务越容易完成，但等待时间和积分消耗也会上升。普通站点先保持默认值。
- 需要联网搜索、第三方数据等外部能力时，在 [MCP 服务](./mcp) 接入 MCP 服务器，不在本页配置。

```text
你是本站的智能助手。回答应清晰、准确、可执行。遇到不确定信息时先说明不确定性；涉及医疗、法律、财务等高风险内容时提醒用户自行核验或咨询专业人士。
```

## 常见问题

### 用户经常看到「模型响应超时，请重试」怎么办？

先在 [模型管理](./model-settings) 用「测试模型」确认模型本身可用。模型可用但开始响应很慢（常见于推理模型，或经网关把一种协议转换成另一种协议的接入方式）时，把「模型首次响应等待上限」调大。

### 单次调用上限越高越好吗？

不一定。上限越高，复杂任务可能更容易完成，但等待时间和成本也会上升。普通站点建议先保持默认值。

### 能设置模型温度（Temperature）吗？

不能。对话、标题生成、上下文整理等模型调用都不指定温度，按各模型服务自己的默认值处理；模型的附加参数里也不能填写 `temperature`。
