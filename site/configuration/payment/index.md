# 支付财务

::: info 扩展包
本组页面由商业扩展包提供（服务端 `COMMERCE_PACK_ENABLED`，管理端 `VITE_COMMERCE_ENABLED`）。关闭或删除该包后，菜单与接口一并消失，对话与工具以不计费方式运行。开关说明见 [扩展包开关与裁剪](/deployment/packs)。
:::

套餐售卖、收款渠道和订单查询都在支付财务里维护。这里决定用户购买套餐时看到什么，以及系统如何确认第三方支付结果。

## 子菜单

| 页面 | 后台地址 | 用途 |
| --- | --- | --- |
| [套餐设置](./package-settings) | `/payment/packages` | 按方案和规格配置用户可购买的周期会员、积分包、价格、有效期和权益文案 |
| [沙箱资源](./sandbox-resources) | `/payment/sandbox` | 按套餐方案分配用户沙箱的内存、CPU、工作区与超时，查看用量 |
| [订单管理](./order-list) | `/payment/order-list` | 查询订单、统计已支付金额、清理未支付订单 |
| [支付配置](./payment-config) | `/payment/payment` | 决定用户端展示哪些支付方式，以及每种方式使用哪个渠道 |
| [支付参数](./channel-config) | `/payment/channel` | 填写微信、支付宝、易支付、PayPal、Stripe 的商户参数，并做完整支付测试 |

账户明细在 [用户运营](../users/account-details) 下。

## 推荐配置顺序

1. 到 [基础信息](../platform/base-configuration) 确认网站地址已经填写为正式域名。
2. 到 [套餐设置](./package-settings) 创建至少一个启用状态的方案和规格。
3. 到 [支付参数](./channel-config) 填写实际收款渠道的商户号、密钥和证书。
4. 到 [支付配置](./payment-config) 开启支付方式并选择渠道。
5. 用「支付测试」发起一笔真实小额订单，到 [订单管理](./order-list) 和 [账户明细](../users/account-details) 核对。

## 扣费规则

模型的计费系数、Token 计费与计费比例在 [模型管理](../ai/model-settings) 里配置；Agent 自动调用工具时也可能产生扣费，流水在账户明细里查看。注册赠送、签到奖励和游客额度在 [用户策略](../users/user-settings) 的「额度与赠送」卡片里配置。

登录用户每次对话开始前只检查可用积分（普通积分加有效的会员积分）是否够一次基础费，实际费用在回复结束后按用量结算：先扣有效的会员积分，不够的部分从普通积分扣。余额不足以支付本轮用量时仍按实际用量扣除，普通积分会变成负数，补足到够一次基础费之前不能开始新的对话；在用户列表「调整积分」里可以补上欠费，但不能再往下扣。访客没有余额可透支，仍是每轮开始前按基础费扣减当日额度。
