# 订单管理

::: info 扩展包
本页功能由商业扩展包提供（服务端 `COMMERCE_PACK_ENABLED`，管理端 `VITE_COMMERCE_ENABLED`）。关闭或删除该包后，本页菜单与接口一并消失。开关说明见 [扩展包开关与裁剪](/deployment/packs)。
:::

用户购买套餐后产生的订单，会进入订单管理。支付排查、财务核对和未支付订单清理，主要都在这里处理。

<!-- 截图占位 CFG-PAYMENT-ORDER-LIST-01：订单管理与金额统计 -->

## 后台入口

- **菜单路径**：支付财务 → 订单管理
- **后台地址**：`/payment/order-list`

## 能做什么

列表页按用户、支付平台和支付状态筛选订单，并显示订单总金额。可以删除单个未支付或支付失败的订单（已支付订单服务端拒绝删除，作为资金审计记录保留），删除后不可恢复；也可以用「删除所有未支付订单」批量删除：实际只删创建超过 24 小时的未支付订单，最近 24 小时内的保留，以免删掉还在支付中的订单，适合定期维护。

## 筛选条件

| 条件 | 说明 |
| --- | --- |
| 用户名称 | 通过用户名模糊搜索用户，再选择用户进行筛选 |
| 支付平台 | 支持易支付、微信官方、支付宝官方、PayPal 官方、Stripe 官方 |
| 支付状态 | 支持未支付、已支付、支付失败、支付超时 |

## 列表字段

| 字段 | 说明 |
| --- | --- |
| 订单ID | 系统生成的唯一订单号，排查支付问题时优先复制这个值 |
| 用户名称 | 下单用户的用户名 |
| 用户邮箱 | 下单用户绑定的邮箱 |
| 套餐名称 | 用户购买时保存的方案和规格名称快照 |
| 商品单价 | 单个套餐的价格 |
| 购买数量 | 本次购买数量 |
| 订单总价 | 本次订单总金额 |
| 支付平台 | 实际使用的支付渠道 |
| 支付状态 | 当前订单支付结果 |
| 订单时间 | 订单创建时间 |

## 支付状态说明

| 状态 | 含义 | 建议处理 |
| --- | --- | --- |
| 未支付 | 用户创建订单后尚未付款 | 可保留一段时间，后续批量清理 |
| 已支付 | 第三方支付已确认，系统应完成发货 | 核对账户明细和用户积分是否同步 |
| 支付失败 | 第三方支付或系统确认失败 | 结合支付渠道日志和订单号排查 |
| 支付超时 | 订单超过有效支付时间 | 通常无需人工处理，可清理 |

## 排查建议

1. 用户反馈付款后未到账时，先用用户名称筛选订单。
2. 确认订单状态是否为“已支付”。
3. 如果订单已支付，再到 [账户明细](../users/account-details) 查看是否有“购买套餐赠送”记录。
4. 如果订单仍未支付：创建 24 小时内的订单会由 [自动补单](./channel-config#reconcile) 核对（每 2 分钟一轮、每轮最多 20 笔，按订单顺序轮转），可以稍后再看；更早的订单或一直没变化的，到对应支付平台后台用订单号或商户订单号查询回调情况。
5. 如果回调未到达，检查 [基础信息](../platform/base-configuration) 的网站地址和 [支付参数](./channel-config) 的渠道参数。

## 注意事项

- 「删除所有未支付订单」只清理创建超过 24 小时的未支付订单，操作前确认没有正在排查的订单。
- 已支付订单不能删除（服务端拒绝），它们是财务核对和售后排查的依据。
- 订单会保存下单时的方案、规格、周期和权益文案快照，后续修改套餐设置不会改变历史订单含义。
- 总金额会随筛选条件变化，可用于按渠道或用户做快速核对。
