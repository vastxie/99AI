# 套餐设置

::: info 扩展包
本页功能由商业扩展包提供（服务端 `COMMERCE_PACK_ENABLED`，管理端 `VITE_COMMERCE_ENABLED`）。关闭或删除该包后，本页菜单与接口一并消失。开关说明见 [扩展包开关与裁剪](/deployment/packs)。
:::

套餐设置用于配置用户端可购买的方案和规格。当前产品口径是：

- **方案**：用户看到的一张套餐卡片，例如“基础版”“专业版”“积分包”。
- **规格**：方案下的具体购买项，例如“月付”“年付”“1000 积分”。

用户端会在一张方案卡片内切换多个规格，实际下单时仍按具体规格的套餐 ID 购买。

## 后台入口

- **菜单路径**：支付财务 → 套餐设置
- **后台地址**：`/payment/packages`

## 能做什么

列表页按套餐状态、方案类型和名称筛选套餐。可以新增方案或在已有方案下新增规格，修改规格的价格、周期、积分等信息；未产生订单的规格可以删除，已有订单关联时建议改为禁用。

## 方案信息

| 配置项 | 说明 | 填写建议 |
| --- | --- | --- |
| 方案标识 | 方案的内部唯一标识，例如 `basic`、`pro`、`credits` | 使用英文、数字、短横线或下划线，后续同一方案下的规格保持一致 |
| 方案名称 | 用户端卡片主标题 | 使用“基础版”“专业版”“积分包”等用户容易理解的名称 |
| 方案类型 | `会员` 或 `积分` | 周期类权益选会员；一次性购买积分选积分 |
| 权益列表 | 用户端权益列表的唯一来源，每行一条 | 写用户能得到什么，不要在其他字段重复维护 |
| 方案说明 | 用户端卡片上的简短说明 | 可写适合人群或使用场景，保持简洁 |

## 规格信息

| 配置项 | 说明 | 填写建议 |
| --- | --- | --- |
| 规格名称 | 方案下的具体购买项名称 | 例如“月付”“年付”“1000 积分” |
| 启用 | 控制该规格是否可购买 | 新规格建议先关闭，完成测试后再启用 |
| 默认规格 | 用户端打开方案卡片时默认选中的规格 | 同一方案同一类型下建议只设置一个默认规格 |
| 周期 | 会员有效期和用户端价格周期的单位；积分固定为一次性 | 会员可选天、周、月、年；积分不需要改 |
| 周期数量 | 与周期组合成用户端文案，并自动换算会员有效天数 | 月付填 1 + 月，季付填 3 + 月，年付填 1 + 年 |
| 价格(CNY) | 人民币售价 | 正式可购买规格必须大于 0 |
| 价格(USD) | PayPal / Stripe 等美元支付使用 | 有海外支付时建议填写，不建议长期依赖换算兜底 |
| 积分额度 | 支付成功后发放的积分数量 | 会员可作为会员积分，积分包作为普通积分 |
| 会员等级 | 会员规格的等级，数字越大等级越高 | 只对会员有意义；积分保持 0 即可 |
| 方案排序 | 方案卡片排序，数字越大越靠前 | 主推方案设置更大数字 |
| 规格排序 | 同一方案内规格排序，数字越小越靠前 | 月付、年付可按运营重点排序 |
| 角标 | 规格上的轻量提示 | 例如“推荐”“省 20%” |

## 用户端展示规则

- 用户端按“方案卡片”展示，规格不会各自单独成卡。
- 用户在方案卡片内切换规格，购买时仍会按具体规格下单。
- 权益列表只读取“权益列表”字段。
- 已禁用规格不会出现在用户端。
- 积分使用一次性规格，不会被展示成自动续费订阅。

## 到账规则

会员规格支付成功后发放会员积分，并按周期和周期数量自动计算有效期，刷新或延长会员有效期；积分规格发放普通积分，不改变会员有效期。

如果用户会员已经过期，再购买任意会员规格，会按新会员处理并从当前时间重新计算有效期。

## 使用建议

- 先创建少量清晰方案，例如一个会员方案和一个积分方案，再逐步扩展规格。
- 同一方案下的规格尽量只改变周期、价格和额度，避免用户切换规格时权益理解混乱。
- 正式运营前，用小额启用规格测试下单、回调和到账。

## 常见问题

### 为什么要区分方案和规格？

方案回答“买哪类权益”，规格回答“怎么买”。月付、年付、季付作为同一方案下的规格切换，不会挤成多张独立卡片。

### 有规格但用户端看不到？

先检查规格是否启用，再检查方案类型和支付配置是否可用。用户端只展示启用规格。

### 会员有效期在哪里配置？

不需要单独填写。会员会按“周期 × 周期数量”自动换算有效天数：天按 1 天、周按 7 天、月按 30 天、年按 365 天计算。积分固定为一次性购买，有效期保持 0。

### 删除规格会影响历史订单吗？

已经产生订单的规格不建议删除。历史订单会保留下单时的方案和规格快照，用于售后和财务排查。
