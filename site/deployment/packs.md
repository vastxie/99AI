# 扩展包开关与裁剪

每个扩展包都有一个服务端环境变量开关；涉及前端页面的包还有一个构建期变量，两者要一起改，前端变量改完需要重新构建。所有开关默认开启。彻底不要的包可以整目录删除。**带数据表的包（商业、内容安全、微信）只能在初始化数据库之前决定开关或删除**，见 [带数据表的包](#pack-tables)。包的能力与分级见 [内核与扩展包](/guide/)。

## 取值规则

- 服务端开关写在 `server/.env`：未设置视为启用，取值 `false / 0 / off / no` 关闭。
- 用户端变量写在 `web/.env.production`，管理端变量写在 `admin/.env.production`：设为 `false` 关闭，改后重新执行 `./dev-build.sh`。

## 带数据表的包 {#pack-tables}

启动时会核对数据库里的表与当前启用的模块**完全一致**：多一张或少一张都拒绝启动（提示「数据库表集合与当前启用模块不一致」），本版本没有迁移工具，不会自动建表或删表。

- **带数据表的包**：商业包（`account_log`、`order`、`package`、`signin`、`user_balances`）、内容安全包（`sensitive_whitelist`、`violation_log`）、微信包（`user_bot_channels`）。它们的开关与删除只能在执行 `db:init` 之前决定；已经初始化、有数据的站点再改动它们会拒绝启动。不要删除这些业务表。
- **不带数据表的包**（邮箱 / 手机号 / GitHub 登录、模型协议、存储、富媒体渲染）随时可以开关或删除，不改变数据库表集合；但仍要重启服务（涉及前端的包还要重新构建），并处理依赖它的已有数据：例如关闭存储包后，已存放在该存储上的文件无法读取，也无法被清理；关闭模型协议包后，配置为该协议的模型无法调用。

## 整目录删除

不需要的包直接删掉三端目录，再从 `.env` 与前端 env 文件里去掉它的开关，重新构建即可：

```bash
rm -rf server/src/packs/<包名> web/src/packs/<包名> admin/src/packs/<包名>
```

用户端、管理端里自带 `package.json` 的包（目前是用户端的 commerce、rich-media 和管理端的 commerce）是该端的 pnpm workspace 子包：删目录后在对应端执行一次 `pnpm install`，锁文件会去掉它的依赖。服务端包的依赖装在 `server/package.json`（`nest build` 按宿主解析依赖），包目录里 `pack.json` 的 `dependencies` 列出只归该包使用的依赖：删目录后可以用 `pnpm remove` 把它们从服务端一并移除。

带数据表的包只能在初始化数据库之前删除（见 [带数据表的包](#pack-tables)）。仓库脚本可以在临时目录里验证删除后的内核仍能通过类型检查与装配测试——它只验证代码，不检查已有数据库：

```bash
node scripts/check-pack-removal.mjs <包名>
```

## 常见组合

- **只要 Agent 基座**（内部工具或二次开发起点）：关闭商业、内容安全、微信三个功能包，登录只留账号密码加邮箱验证码。
- **对外运营**：全部开启，再按实际情况关掉用不到的登录渠道、模型协议与存储厂商。
- **海外站点**：关闭微信包与手机号包，保留邮箱、GitHub 登录和 PayPal / Stripe。
