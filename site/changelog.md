## 0.1.0 测试版（2026-10-26）

99Agent 的首个公开测试版，代码与后续维护统一在 99AI 仓库。它是旧版 99AI 的新一代重写，数据库、配置与部署方式均不兼容，请全新部署；旧版克隆请备份后重新克隆。

### ✨ 新增

- 多用户 Agent 对话：账号注册登录与会话管理；模型网关内置 OpenAI Chat Completions 兼容接口，OpenAI Responses、Anthropic、Gemini、OpenCode Go 由各自的模型协议包接入；回复流式输出，工具调用过程实时可见。
- 能力扩展：沙箱内的技能（`skills/`）、MCP 服务器（后台「AI 能力 → MCP 服务」管理）、垂直业务清单导入。
- 管理后台：平台设置（站点、文件存储等）、AI 能力（模型、MCP 服务）、用户运营、登录接入。
- 可裁剪的扩展包：商业（积分、套餐、订单与支付）、内容安全、微信（登录、公众号与 Bot 通道）、邮箱 / 手机 / GitHub 登录、S3 / OSS / COS 存储、用户端富媒体渲染。删掉任意一个包，内核照常构建和运行，见[内核与扩展包](/guide/)。
- 用户端：中英文界面（数字、日期按界面语言书写）；明暗主题首帧不闪；键盘与读屏可用（弹窗、设置、搜索、登录表单的焦点与播报）；公式、代码高亮、代码编辑器、支付等较重的功能用到时才加载；断线后回复自动接上，重新生成、排队补充要求与多页签草稿都按服务端结果对账。
- 每个登录用户拥有一台自己的沙箱电脑：多个对话共用、可以同时执行任务；工作区是该用户独立的持久磁盘，生成的文件、装过的软件和设置都会保留，删除对话也不会删除它在电脑里的目录。访客仍是每个对话一台临时环境。
- 管理后台「沙箱资源」可按套餐方案设置每位用户的磁盘容量，与内存、CPU 一起分档；磁盘写满即停，调大在下次开机时生效，调小不删除文件。
- 用户磁盘提供本机备份与按用户恢复命令，备份超期会给出提示，便于接入监控。
- 对话支持上传 zip 压缩包（例如批量商品图、素材包），由沙箱解压处理；同时补上 .ppt 文件的上传。
- 对话里生成的 HTML 网页可以在侧栏直接预览运行（与 HTML 代码块预览同一隔离环境，拿不到本站登录信息）。
- 回复更聚焦：模型执行过程中写的过程说明不再混进正式回复，运行时以较淡的一段显示在状态行上方，给出回复后收进活动面板；达到轮次上限等没有回复的情况，也不再把过程说明当作回复保存。
- 模型可以挑出这次回复的成果文件（按顺序、可附说明）放在回复末尾，脚本、中间数据等收进可展开的「过程文件」；微信 Bot 只发送挑出的成果文件。
- 模型需要你确认或选择时会提问并给出选项，点选项即可作为下一条消息发出；微信 Bot 以编号选项的文字发送。
- 服务端每天自动清理到期的用户文件（与后台「执行过期清理」同一套条件：已到保留期、保存失败、处理超时的文件），以前只能手动清理；间隔可用 `FILE_ASSET_CLEANUP_INTERVAL_HOURS` 调整，设 `0` 关闭。
- 支付通知丢失或服务重启后，后台每 2 分钟自动核对创建 24 小时内的待支付订单，查到已付款且订单号、金额、币种都一致时自动入账；PayPal、Stripe 也能查询了（PayPal 只确认已完成的付款，Stripe 有退款或争议的付款不自动入账）。可用 `PAYMENT_RECONCILE_ENABLED=false` 关闭。
- Claude 模型按具体型号发送推理参数（自适应思考或手动思考预算、能否关闭、可用强度），并自动调整输出上限、采样参数与强制调用工具，见[模型设置](/configuration/ai/model-settings#claude-reasoning)。模型目录新增 Claude Opus 5.5、Sonnet 5.5、Fable 5.1、Mythos 5.1、Fable 5、Mythos 5、Opus 5、Sonnet 5，并按型号预设推理档位。

### 🎉 优化

- 安装依赖时校验 SheetJS 表格库下载包（官方 CDN）的完整性：锁文件补上摘要，CDN 上的包一旦变化，安装会直接失败而不是装进不同的内容；CI 也会检查锁文件里的下载包都带已审核的摘要。
- 启用全新的默认标志：用户端侧栏与登录框、浏览器标签页、添加到主屏幕的图标，以及管理后台、文档站的标签页图标统一更新；已在后台配置自定义 Logo 或 favicon 的站点不受影响。
- 引导模型先在对话目录里试跑，只把最终版本放进交付目录，减少同一文件被反复交付。
- 任务接近「工具调用轮次上限」时，会在最后几轮提醒模型停止继续搜集、整理已有结果并交付，轮次用完后还能给出一次最终答复，减少长任务在上限处被截断、什么都没交付的情况。
- 回复达到模型单次输出上限时，在回复下方提示「可能没写完」，可以继续追问让它接着写；以前会当作正常完成。
- 登录用户对话结束时余额不足以支付本轮的实际用量，现在照常完成回复并按实际用量扣费（余额可能变为负数，充值后才能继续对话）；以前会显示「处理请求时发生错误」。
- 微信 Bot 在后台关闭后立即停止接收消息、不再发起新的对话（已在生成的回复会照常发完），绑定入口同时关闭；重新开启后自动恢复已绑定的用户，不需要重启服务。
- 模型可用的技能列表现在也会列出说明文件（SKILL.md）超过 4 KB 的技能，常见的公开技能不再被静默略过。
- 不再统一设置模型温度（Temperature）：对话、标题生成、上下文整理与连接测试都按各模型服务自己的默认值调用，后台「全局配置」里的 Temperature 设置项移除；部分新模型不接受温度参数，不再因此报错。
- 第三方登录入口只在必需的配置都齐时出现：GitHub 与微信开放平台网站登录还需要回调地址或网站地址，公众号扫码还需要服务器 Token，微信内授权还需要网站地址；配置不全时登录框和账号页不再显示一个点了必定失败的入口，补齐后自动恢复。
- 界面语言只在用户手动切换时保存：没有选过语言的用户每次打开（或刷新）页面时按后台当前的默认语言显示（取不到站点配置时按简体中文），后台改了默认语言也随之变化；保存的语言被后台停用时暂按默认语言显示，重新启用后刷新页面即恢复；多开页签时，一个页签读取站点配置不会再改写或删掉另一个页签刚选的语言。
- 管理后台「AI 能力 / 全局配置」新增「模型首次响应等待上限」（默认 120 秒，可填 10–600）：推理模型、经转换网关接入的模型开始响应较慢时，不再被固定的 30 秒上限判为「模型响应超时」。
- 命令输出超过捕获上限时保留开头和结尾（以前只留开头）：报错与结果通常在结尾，Agent 第一次就能看到，不用再重定向到文件重读一遍。
- 模型选择成果文件、向用户提问这两个动作的结果原话交给模型：不再套「文件解析摘要」并截断，找不到文件时能看到完整的可选文件清单。

### 🐛 修复

- 修复断线重连恰好赶上回复收尾、而这条回复又交接给排队的下一轮时，下一轮回复的开头可能带上上一轮正文的问题；补发同步给出的收尾原因（交接给下一轮、输出达到上限）也会照常处理。
- 修复实时连接刚建立时第一条消息偶尔被提示「请先登录」的问题：服务端改在建立连接的握手阶段完成鉴权；鉴权服务暂时不可用时不再当成登录失效，连接会在核对身份后自动恢复；切换账号或退出时，进行中的发送、停止与回复续接会立即结束，不再等待超时。升级后如果实时消息或回复续接异常，刷新一次页面即可。
- 修复同一邮箱或手机号几乎同时首次验证码登录（或同时被两个账号绑定）时，可能出现两个账号使用同一联系方式的问题：现在由登录身份的唯一记录裁决，后到的请求直接登录到先建好的账号，或提示「该联系方式已被其他账号绑定」；数据库认为相同的写法（大小写、重音）同样只归一个账号。验证码登录与找回密码（验证验证码之后）遇到联系方式的归属数据冲突时，提示联系管理员处理；锁定或封禁的账号不能再通过验证码登录。
- 修复开着思考的 Claude、Gemini 模型多次调用工具时，下一次请求缺少上一步的思考块或思考签名、可能被模型服务拒绝或推理中断的问题：同一次回复里会原样带回（签名等回放内容只在内存里，不保存、不显示；思考过程正文照常显示）；Claude 在对话被整理后不再带回，带着思考块被拒（HTTP 400）时自动去掉重试一次，见[模型设置](/configuration/ai/model-settings#thinking-replay)。
- 修复 Gemini 的思考摘要被当成回复正文显示的问题，现在显示为思考过程。
- 修复浏览器禁止网站保存数据（隐私模式、浏览器或策略设置）时页面打不开的问题：现在照常加载，语言与明暗模式可以切换（只是不会记住，下次打开回到默认）；登录状态存不进浏览器时提示一次「刷新页面后可能需要重新登录」。
- 修复多轮对话中只调用工具、没有文字的回合在之后的上下文里被当成「已中断」、丢掉工具调用与结果的问题。
- 修复模型在工具结果里看到的文件编号与按编号读取到的文件可能不一致的问题。
- 修复联网任务中沙箱出口代理因连接被中途断开而退出、导致该用户后续联网请求全部失败的问题。
- 修复模型读取本轮刚交付的文件时报「文件不存在」：交付后文件会移入归档目录，现在按原路径读取会自动读取归档副本。
- 修复沙箱命令超过时间上限被终止、或命令完成后文件交付出错时整轮回复直接失败的问题：现在会把原因告诉模型，由它调整后继续完成任务；被终止的命令写到一半的文件会先挪到一旁暂存，不会当作成品交付。
- 修复沙箱命令里启动了后台进程（例如 `python3 -m http.server &`）却没有把输出重定向到文件时，工具调用一直等到后台进程退出、整轮卡住的问题：现在主命令结束后很快返回，提示输出未结束、本次暂不交付文件，不会主动结束这些后台进程（输出没有重定向的后台进程之后可能出错或卡住，需要后台运行时应把输出重定向到文件）；每条命令在服务端也有截止时间，沙箱异常时不再无限等待；停止回复时会尝试结束正在运行的命令，几秒内停止等待。
- 修复修改密码成功后页面仍保持已失效的登录状态：现在提示用新密码重新登录，没发出去的草稿保留。
- 修复个人指令还没加载出来时就能保存、把原有指令清空的问题；关闭再打开时较早的加载结果也不会覆盖内容。
- 修复会话列表临时加载失败时，打开的会话地址被跳回首页：现在保留地址并提供重试，断线重连拉到列表后会自动打开；重连后也不会误离开刚切换到的会话；会话还没打开时按发送只会提示，不会把消息发到别的对话。
- 修复生成中切换对话后，排队中的模型选择被保存到另一个对话的问题。
- 修复搜索时改了关键字立即按回车，仍会打开上一个关键字结果的问题。
- 修复生成中粘贴或拖入文件仍会开始上传、随后又无法加入下一轮的问题：现在直接提示，等这一轮结束再添加；附件卡片上的移除、重试按钮现在可以用键盘操作。
- 修复消息里的私有图片在内容快速变化时偶尔显示不出来或被重复加载的问题；活动详情面板打开时会跟随实时进度更新；几十万行的小表格文件可以正常预览。
- 修复签到弹窗长时间开着或跨天后，仍按前一天判断是否已签到的问题；修复按美元价支付时支付页报错的问题。
- 修复开启「减弱动态效果」后历史消息加载提示仍在跳动，以及部分旧版浏览器、强制色模式下滑块的键盘焦点看不见的问题；手机上的侧栏抽屉可以按 Esc 关闭，打开时焦点留在抽屉里，关闭后回到打开它的按钮。
- 修复访客网络断开后重新连上时，被换成一个新的访客身份、原来的对话都看不到的问题；服务暂时故障（如缓存服务短暂不可用）时，已登录用户不再被当成登录过期而退出，访客也不会被换掉身份。
- 修复登录、退出或登录过期前后发出的请求结果落到新身份上的问题：旧身份的资料、账户余额、会话列表与消息不再覆盖新身份；登录前发出、登录后才回来的「未登录」响应不再把刚登录的账号退出；本页用一种方式登录成功后，同时进行中的另一次登录（账号密码、验证码、扫码、第三方登录回调）不再覆盖它。
- 修复点停止后马上再发一条消息时，上一条的提交结果晚到会清掉新输入的草稿或解开新消息的发送状态的问题。
- 修复点停止后，停止请求其实没送到或被拒绝、回复仍在生成，却被显示成「已停止」的问题：现在停止请求经服务端受理后才显示已停止；暂时无法确认时提示稍后重试，回复照常显示；回复其实已经结束的，按服务端的记录核对后更新。停止被拒时，仍在生成的回复也不再被显示成出错。停止一条跟丢的回复时，正在生成的另一条回复的停止按钮照常可用。
- 修复切换对话或回复接续下一轮时，断线后的补发仍按上一条回复的进度请求、迟到的补发结果干扰当前回复的问题。
- 修复管理后台快速连续切换开关或修改配置时，最后一次操作没有保存、或界面与实际保存的值不一致的问题：同一页面的保存按顺序提交，以最后一次为准；保存失败时回到上一次保存成功的值（正在输入的新内容保留）。互斥的两个检测开关、支付参数的「清空配置」、启用语言与默认语言改为一次提交、失败一起恢复；访客开关跟随每日积分额度。
- 修复管理后台列表翻页或筛选较快时，较早的结果晚到覆盖新结果的问题；筛选栏「重置」后旧关键词不再被写回，筛选面板里选中或清空后，之前的搜索结果晚到也不再覆盖候选。
- 修复账户明细里管理员扣减积分显示成绿色「+」的问题：正负号与颜色都按实际增减显示；工具调用消费显示为「工具调用」。
- 修复支付测试弹窗在 PayPal、Stripe 等美元渠道仍按人民币显示金额的问题；首次保存公众号凭据后，菜单管理无需刷新页面即可使用；「展示用户协议」开关的说明改为与实际效果一致（登录 / 注册处展示协议链接，不需要勾选）；用户名单元格可以用键盘打开用户详情，没有权限的账号只显示文字。
- 修复模型列表启用开关快速切换时状态错乱、保存后整页刷新的问题。
- 修复 MCP 服务页面加载失败或有人同时修改时，保存会用不完整、过期的列表覆盖后台已有服务器的问题：保存会核对页面最近一次读取或保存时的版本，被别人改过就提示刷新；正在刷新或加载失败时不允许修改；后台配置里有无法解析的条目时，保存前先确认丢弃。命令行导入 MCP 服务器同样核对版本、不覆盖无法解析的现有配置，预演与正式导入用同一套检查。
- 修复复制模型、导入模型配置后保存时 API Key 被静默清空，以及测试连接、获取远端模型列表时把脱敏的 Key 发给模型服务商的问题：复制与导入导出不再携带 Key，新建模型必须填写 Key。
- 修复配置接口与垂直包导入里，配置项名称只差大小写（如 `McpServers`）时绕过专用入口、密钥脱敏与取值校验的问题：现在直接拒绝并提示原名。
- 修复部分模型调用工具时会把用不到的参数也填成空值（例如 `recover_outputs: false`、空的技能名），导致沙箱命令始终被当成「重试交付」而无法执行的问题。
- 修复已登录用户刷新套餐页面时偶尔误弹登录框的问题。
- 订正多处与实际不符的文档：初始管理员密码（取 `ADMIN_INITIAL_PASSWORD`，未配置时随机生成）与「重置密码」（随机临时密码），都没有固定的 `123456`、带数据表的扩展包只能在初始化数据库之前裁剪、部署与开发命令统一从仓库根目录执行、对象存储需要删除对象的权限、模型各协议的实际请求地址、订单删除规则（已支付订单不能删，批量只删 24 小时前的未支付订单）、内核数据表清单。

### ⚠️ 升级须知

- 测试版：1.0 之前接口、配置项与数据库结构都可能调整，暂不提供数据迁移。用于生产前请先在独立环境验证，并备份数据库与上传文件。
- 旧版 99AI 的数据库不能直接升级到 99Agent，请按[安装部署](/deployment/)全新部署：对空库执行 `node dist/main db:init`，正常启动不会自动改表。
- 访问端浏览器：Chrome / Edge 111+、Firefox 114+、Safari 16.4+（iOS 16.4+），Mermaid 图表另需 Safari 17.4+；在微信里打开请使用较新的微信版本。
- 用户沙箱需要宿主机安装 Docker，生产环境另需 gVisor，安装步骤见仓库里的 `sandbox/README.md`。
- 每个联网会话额外预留 128 MiB 代理内存；更新采用新沙箱资源布局，先结束旧会话并核对清理旧资源。gVisor 必须通过工作区字节与文件数量硬上限验收，具体版本补丁与步骤见仓库 `sandbox/README.md`。
- 登录用户的沙箱改为每人一台持久磁盘：生产环境升级前须按 `sandbox/README.md`「用户磁盘」安装宿主磁盘助手并设置 `SANDBOX_USER_DISK_ROOT`，暂时不能安装时显式设 `SANDBOX_USER_STORAGE=tmpfs`；两者都没有时服务拒绝启动。启用持久磁盘时，`SANDBOX_NAME_PREFIX` 只能包含字母、数字、点、下划线和连字符，并以字母或数字开头。
- 升级后首次启动会回收登录用户旧的每对话临时环境，其中尚未保存的临时成果会丢失；请在升级前让用户完成进行中的任务。
- 升级后服务启动约 5 分钟会第一次自动清理到期文件（之后每天一次），积压较多时会分多次处理；使用对象存储时请确认访问密钥有删除对象的权限（见文件存储文档），多实例部署请只在一个实例上开启（其余设 `FILE_ASSET_CLEANUP_INTERVAL_HOURS=0`）。
- 第三方登录的回调地址必须与用户访问的站点同源（协议、域名、端口都相同；公众号内授权按「网站地址」判断），不一致时点登录会提示检查回调地址配置；站点有多个访问域名时，请让用户从回调地址所在的域名登录。升级时已打开的旧页面需要刷新后再使用第三方登录，升级前已发起、还没完成的授权需要重新发起；浏览器禁用网站数据时无法使用第三方登录。回滚到更早的版本会同时撤销这项登录防护。
- 存储桶名或地域不符合厂商规则时（以前会被悄悄删改字符，或带大写字母照用），升级后上传会提示「存储桶名不合法」，地域不合法时所有文件操作都会提示「存储地域不合法」，请在后台改成正确的值（地域只用小写字母、数字和短横线）；已有文件按记录里的存储桶照旧访问。第三方登录入口在必需配置不全时会隐藏，升级后某个入口不见了，按登录配置文档补齐即可。
- 使用提示缓存的 Claude 模型，记录与扣费的输入 token 会包含缓存读写（以前漏算）：按 Token 计费的模型可能比以前多扣积分，缓存读写按平台统一的输入口径计费，需要时可在后台调整模型倍率。
- Claude 模型开思考时的默认输出上限提高到 16384（手动思考为预算 + 4096），可能增加实际输出与费用，需要更低上限时在附加参数写 `max_tokens`。已添加的 Claude 4.5 / 4 / 3.7 模型保持原来的默认档位（新选目录条目才默认「关闭」）；网关自定义别名等识别不出的 Claude 模型不再自动加推理参数，需要时在附加参数里手写 `thinking`。建议升级后对 Claude 模型重新运行一次「真实探针」。
- 支付自动补单默认开启：多实例部署请只在一个实例上开启（其余设 `PAYMENT_RECONCILE_ENABLED=false`）。停止服务时，正在进行的补单入账未提交的整体回滚、已提交的保留；重启后，仍在 24 小时内、仍是「未支付」且补单开启的订单继续核对。
- 等待模型开始响应的默认上限由 30 秒改为 120 秒：上游接受了请求却一直不响应时，用户会多等一会儿才看到超时提示；需要更快失败或更长等待时在「AI 能力 / 全局配置」调整。
- 移除三个没有界面在用的接口：`POST /api/chat/system-chat`（超级管理员直接调用默认模型）、`POST /api/chatlog/deleteChatsAfterCid`（删除某条消息及之后的消息；重新生成与编辑重发早已改为随新一轮在同一事务里替换）、`GET /api/files/admin/stats`（文件占用统计）。自己写脚本调用过这些接口的需要调整。
