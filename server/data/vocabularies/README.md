# 敏感词库（自备）

仓库不附带任何敏感词库。内容安全扩展包的「本地敏感词库」功能从本目录读取部署者自己准备的词库文件；本目录下除本说明外的文件都被 `.gitignore` 忽略，不会进入版本库。

## 文件格式

- 每个词库一个 UTF-8 文本文件，扩展名 `.txt`，文件名（不含扩展名）就是管理端显示的词库名，例如 `广告词.txt`。
- 一行一个词。首尾空白、`\r`、制表符会被去掉；空行和以 `#`、`//` 开头的注释行会被跳过；同一文件内重复的词只算一次。
- 文件名不能包含路径分隔符。

## 生效方式

1. 把词库文件放到本目录（`server/data/vocabularies/`）。
2. 在管理端「安全风控 → 内容审核」开启「使用本地敏感词库」，勾选要启用的词库；多个词库合并去重。
3. 替换或新增文件后重启服务，词表按词库名缓存在进程内。

目录不存在或为空时服务照常启动，本地词库按空处理，不会拦截任何内容。

## 部署

`build.sh` 默认不把本机词库打进发版包，避免随公开分发的压缩包流出；给自己部署打包时用 `INCLUDE_VOCABULARIES=1 ./build.sh`。手工部署时把本目录与 `dist/` 一起分发，服务需在 `server/` 目录下启动，或让 `dist/` 旁边存在 `data/vocabularies`。

用 git 更新代码前先备份本目录的 `.txt` 文件：仓库不跟踪它们，早期版本随仓库附带的词库在更新时会被删除。
